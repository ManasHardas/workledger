# Checkpoint notes

## Session 2

- `checkpoint.ts` is the only validated write path into the ledger and fails closed: it runs the contract's eight steps in order (resolve session, byte-cap/parse/validate plus ref check, secret-scan the payload, build the stamp, render session and backlog text, scan every rendered byte, atomic writes, ack line), and any failure before step 7 writes nothing. Failures are cached in the index via `recordAttempt` for the Stop hook, except on `--dry-run`, which is a rehearsal rather than an attempt.
- Nothing this command says about a rejected payload can leak a value: `JSON.parse` messages are reduced to a byte offset, unknown-key names become positional `<key#N>` markers, and every stderr line passes through `redactLine` (the scanner) on the way out. The checkpoint number `n` is predicted early for the goal rule but allocated inside the index's `BEGIN IMMEDIATE` transaction, so a secret found at step 6 throws `SecretDetected` and rolls the row back.
- `ledger-fs.ts` is the only place ledger text touches disk. `findRepoRoot` walks up to the nearest `.workledger/` or `.git/` without resolving symlinks (so one repo never forks into two index keys); `writeFileAtomic` writes a pid-plus-counter temp file in the same directory and renames over the target, removing the temp on failure; and `listOpenBacklogIds` lazily imports the backlog parser (the `yaml` init cost the Stop allow path cannot afford) and skips unparseable files rather than failing every checkpoint in the repo.

## Session 3

- The stamp degrades rather than refuses. `stampTrigger` falls back to `manual` when there is no pending block, the recorded trigger column is null, or the value is one this build does not know, and `stampOffset` keeps the index's `last_offset` when the transcript is unreadable or unrecorded. Both fields are provenance, and losing provenance is not worth rejecting a valid digest; the offset rule also guarantees the covered span `[offset(n-1), offset(n))` never runs backwards.
- Session resolution at step 1 has three tiers and is the one failure that is not cached: `--session`, then `WORKLEDGER_SESSION`, then the single open session for the repo root. Zero or multiple open sessions is a usage error that lists the ulids, and because there is no session row yet, `recordAttempt` is never called, so the Stop hook cannot retry-block on it. Every later failure goes through the `fail` closure, which redacts, prints, and records the attempt in one place.
- `runCheckpoint` is written against an injected `CheckpointIo` (stdin bytes, both output streams, cwd, env, clock, ULID factory) so tests drive the whole path in-process against a temp repo and temp `WORKLEDGER_HOME`; `checkpointCommand` is just `runCheckpoint(options, processIo())`. Related hygiene: `readAll` stops buffering one byte past `MAX_PAYLOAD_BYTES`, hand-edited session lines are reported only as a per-section count (they have not been scanned), and step 5 renders backlog texts into memory and holds them so step 6 can scan every byte before step 7 lands any of it.
