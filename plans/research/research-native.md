## Per-platform findings

### 1. Anthropic — Claude Code + Claude Platform
Two different things, and the distinction matters.

**Claude Code (the coding agent) has no org memory.** Auto memory is on by default but machine-local, per-repo, and holds preferences/corrections/light project notes (E-N1, E-N2). The broadest *shared* mechanism is a managed-policy CLAUDE.md pushed by MDM — org-wide, but human-authored static instructions (E-N3): the proposal's category B, not C. Agent teams cannot outlive or span a session (E-N7); cross-session messaging is your own sessions only, plain text, unpersisted (E-N8); web session sharing gives humans an org-visible transcript link, not an agent-queryable record (E-N9).

**Claude Platform (Managed Agents) has both the storage primitive and the extraction pipeline.** Memory Stores are workspace-scoped, attachable to many sessions, mountable read-only as "shared reference material", explicitly recommended as "one store per end user, per team, or per project", and every write produces an immutable, session-attributed version = a real audit trail with redaction (E-N4, E-N5, E-N6). On top of that, **Dreams** (research preview) reads 1–100 **past session transcripts** plus an existing store and synthesizes a reorganized store with contradictions resolved and "new insights surfaced" (E-N30). That is precisely §7 and §17 of the proposal — raw agent activity → extraction → durable structured knowledge, with human review before adoption — running as a first-party API today.

The gaps are real but narrow: it is a bring-your-own-schema markdown filesystem, not a Work/Decision/Discovery/Provenance model; it is Anthropic-locked; and it is reachable only from Managed Agents sessions, **not from Claude Code**. The proposal's differentiator against Anthropic is therefore the *schema* and the *cross-vendor ingestion*, not the storage or the extraction — Anthropic has already built both of those.

**Signal of intent:** `CLAUDE_MEMORY_STORES` and the phrase "mounted **team** memory stores" appear in the Claude Code CHANGELOG at v2.1.172 (E-N10) but in **none** of the four relevant docs pages. Something team-scoped exists in the binary and is undocumented. Meanwhile the community feature request for exactly this thesis (#38536, March 2026) sits open with no maintainer reply (E-N11).

### 2. OpenAI — Codex
Per-user, per-machine, preferences-grade. Memories live in `~/.codex/memories/`, do not sync across devices, and the docs actively push team knowledge *out* of memory and into checked-in files: "Keep required team guidance in `AGENTS.md` or checked-in documentation" (E-N12). AGENTS.md has global + per-repo scope with no org tier (E-N13). The 2026 changelog work is context-window engineering (token-budget sessions, history/notes tools), not org state (E-N14). **OpenAI is the furthest from this thesis of the four majors.** No "Symphony" product was found in any OpenAI primary source.

### 3. Cursor
Org-wide **instructions** are shipped and enforceable (Team Rules, E-N27) — but there is no Memories page in Cursor's docs index at all today (E-N28). Cursor has cloud agents, subagents, and automations, but no documented shared knowledge store extracted from agent sessions. Agent-locked to Cursor.

### 4. GitHub — the most threatening
Copilot Memory is category-C-adjacent and shipped: repo-level facts including "architectural decisions", shared across **all users with repo access** and across **three Copilot agents**, with **citations as provenance**, just-in-time re-validation against the current branch, and 28-day decay (E-N15–E-N19). Nobody else has shipped provenance + freshness this concretely at this scale.

Its limits are equally concrete: **repo-scoped, not org-scoped** (E-N18); **Copilot-only** — no Claude Code, Codex or Cursor session ever writes to it; it stores facts about the codebase, not work state, approvals, rejected alternatives, ownership, or active work; and GitHub's own engineering post makes **no** system-of-record claim (E-N18). Agent HQ tracks *runs*, not *knowledge* (E-N20). Copilot Spaces is a curated human context bundle whose docs never say the coding agent reads it (E-N21).

### 5. Linear
Linear has shipped the best **agent activity/session model**: AgentSession as a first-class lifecycle object, vendor-agnostic, created automatically on mention/delegation, with `thought` activities and a `promptContext` (E-N23). Coding sessions run Claude Code and Codex from an issue (E-N24). But it is issue-scoped: no documented cross-issue knowledge base, no decision record with alternatives/approvers, no query surface for "what does the org already know about X". Linear owns the *work item* and now the *agent run*; it does not own the *knowledge*.

### 6. Atlassian — the loudest positioning
Two moves. (a) Team '26, May 2026: the Teamwork Graph opened to third-party agents via a CLI and the Rovo MCP server, explicitly so Claude Code and Codex can read org context (E-N25). (b) July 2026: Jira Automation reframed as "an **open control plane** for AI coding agents with native support for GitHub Copilot, Cursor, and Claude", where "an event in **your system of record** can now automatically package structured context, trigger the right agent, and log the outcome" and "every agent invocation is logged in Jira's audit trail" (E-N26).

This is the only vendor making the proposal's *positioning* claim out loud, and the only one claiming agent-independence as a feature. What it does not appear to have: extraction of knowledge *from* agent sessions (the flow is Jira → agent, not agent → record), a discovery/claim/decision model distinct from work items, or engineering-grade provenance. Its record is an audit log of invocations, not a knowledge graph of what was learned.

### 7. Tier-2 vendors — where the thesis is actually already being built
This tier, not the majors, contains the real prior art.

**Warp is the closest thing to this proposal that exists.** Agent Memory is cross-harness by design — one store shared across the Warp Agent, **Claude Code and Codex** — with Personal / Agent / **Team** stores, automatic extraction of "durable facts, learnings, and **outcomes**" from transcripts, and explicit provenance: "Each memory records where it came from, so teams can trace a memory back to its source" (E-N31, E-N32). Memories surface as citations. It is agent-independent, team-scoped, transcript-derived and provenance-carrying — four of the proposal's five load-bearing properties. It is in **research preview, design-partner-gated**, and it is Warp-hosted rather than org-owned.

**Notion Lore** ships the decision model the majors lack: a `lore-decision` tool **with supersede**, alongside fact/task/procedure, wired into Claude Code, Codex and Cursor hooks, explicitly cross-person — "agents on one person's desk could learn from the experiences of another person's agents" (E-N33). It is a 20% side project with ~121 stars, not a Notion product. Existence proof, not competition.

**Augment Cosmos** ships org-shareable Experts Memory holding "durable information that could change a future decision", plus a Code Review Memory Manager that converts review feedback into durable guidance, plus an agent-independent Context Engine over MCP (E-N34). **Devin** has the most complete shipped knowledge stack — org/repo-scoped Knowledge with auto-suggestion, and DeepWiki exposed to other vendors' agents via MCP — but its content is conventions and workflows, not rationale (E-N36). **Factory** makes the boldest claim in the market — "Org and User-level Memory: **Captures decisions**, docs, and run-books" — with **no memory page anywhere in its docs index** (E-N35); treat as marketing.

Negative: **Amp** has the richest shared substrate in the market (org-shared threads by default, a searchable org-wide feed) and has shipped **no** memory feature — zero occurrences of the relevant terms on its news page (E-N37). **OpenCode** has nothing (E-N40). **Google** is file-based and per-repo at both Gemini CLI and Jules (E-N39). **Windsurf** is now Devin, and Cascade memories explicitly do not cross workspaces (E-N38).

### 8. Slack / Notion as platforms
Slack's MCP server and Real-time Search API (GA 2026-02-17) give agents permission-aware access to conversations "as they exist in the workspace" and explicitly do **not** store data externally (E-N41) — a retrieval layer over chat, with no decision or rationale model. Notion's hosted MCP is general-purpose read/write with no memory framing; the interesting artifact is Lore, above.

### (b) Conspicuously NOT covered by anyone
1. **Human accountability.** No vendor models proposer vs. **approver**, approval authority, or "the organization has decided X" as distinct from "an agent believes X". The closest artifacts are Jira's audit log of invocations (E-N26) and Memory Store version attribution (E-N6). Proposal §8/§9 is genuinely unclaimed.
2. **Rejected alternatives / negative knowledge.** "This was tried and it failed", "this was proposed and rejected because it breaks payments" appears in **no** shipped schema anywhere — not Copilot, not Warp, not Devin, not Lore. This is the single cleanest gap.
3. **Active-work awareness across an org.** GitHub mission control and Linear AgentSession show *runs in flight* per repo/issue (E-N20, E-N23); Anthropic's view is per-user (E-N8). Nobody answers "which agents are currently touching this subsystem".
4. **Org scope above the repo, for knowledge.** Copilot is hard-scoped to one repo by permission model (E-N18); Anthropic auto memory is per-git-repo (E-N1); Jules is per-repo (E-N39). Warp and Augment do cross the boundary — both preview/newer.
5. **Cross-vendor is thinning fast, not absent.** Warp (E-N31), Augment Context Engine, Devin DeepWiki MCP, Notion Lore and Atlassian's Teamwork Graph MCP are all agent-independent today. **Agent independence alone is no longer a defensible wedge.**

### (c) The single most threatening first-party move
**GitHub Copilot Memory graduating from repo scope to org scope.** It already has the three hard parts shipped and defaulted-on: extraction from agent sessions, provenance via code citations, and freshness via just-in-time re-validation with 28-day decay (E-N15–E-N19). It is already shared across users and across three Copilot agents, and it already stores "architectural decisions". Everything the proposal claims is hard is running in production at GitHub — one scope boundary away — and GitHub owns both the distribution and the permission model needed to widen it.

Runners-up, in order: **Warp Agent Memory** graduating from research preview — it is the only shipped design that is simultaneously cross-harness, team-scoped, transcript-derived and provenance-carrying (E-N31/32), i.e. it is this proposal minus the schema. **Anthropic** wiring Memory Stores + Dreams into Claude Code — the storage and the extraction pipeline both exist as APIs today (E-N4/E-N30), and `CLAUDE_MEMORY_STORES` suggests the plumbing is already in the binary (E-N10). **Atlassian**, which holds the positioning ("your system of record", "open control plane", E-N26) and cross-vendor reach (E-N25) but lacks engineering-grade extraction from agent sessions.
